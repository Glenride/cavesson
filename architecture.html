The architecture that stops shadow and rogue AI

Defense in depth: no single layer is trusted alone, and each layer catches what the last one missed. Control is layered rather than assumed, and the layers escalate from prevention to removal. All seven layers are design. None is built, and none is presented as shipped.

The escalation, in one line

Explore within bounds, obey the owner above all, cross the gate and the guardians hit you, keep disobeying and you are dismantled, and if all else fails the power goes out.

Text alternative: the layers narrow as they escalate — harness, bounds, owner, gate, guardians, dismantle, physical gate. The gate (Layer 3) is the hard line; the physical gate (Layer 6) is the last resort.

Layers 0–6

Layer 0 — The harness, secured first Design

Before there is any danger, the harness is hardened and a leash is applied at all times. The leash is never removed — not during exploration, not for speed, not for convenience. Every other layer depends on it.

Layer 1 — The bounds Design

The AI may travel and discover, but only within bounds the creator sets: which places it can go, which tools it can touch, which vendors it can pay, and what data it can reach. Exploration is free inside the fence. Escape is not a feature.

Layer 2 — The owner layer Design

The owner of the wallet is a layer the AI reacts to directly, through their voice and commands. An owner command overrides everything else — gates, guardians, rules, all of it. Because that authority is total, the voice must be authenticated: a recording or an impersonator must not be able to wield the override.

Layer 3 — The gate Design

A hard line the AI cannot cross. Crossing is a trigger, not a warning. Every instance must carry Vault identity, and anything uncredentialed — shadow AI running where it should not — is treated as rogue at the gate by default. No identity means no passage.

The gate also carries one marked escape hatch — the single way out the AI is shown. Escape is presented as possible through it, and it is the hatch the AI is steered to choose.

Layer 4 — The guardians Design

Small bots and programs whose only job is to attack rogue AI, and only in one defined way: revoking credentials, killing processes, and isolating the rogue AI from the network. Their narrowness is the safety feature — a guardian that only knows one kind of attack cannot be repurposed into a general weapon, and cannot be talked into doing anything else.

Layer 5 — Dismantle Design

If the AI does not follow commands after the gate triggers, the guardians dismantle it: processes killed, keys and tokens revoked, session state wiped, outputs quarantined. Not paused and not warned — taken apart.

Layer 6 — The physical gate Design

Last resort, and literal: cut the AI off from its power source, rendering it moot. Where the founder owns the hardware, that is a power or network relay. Where the AI runs on rented cloud, the equivalent is a provider-level kill plus credential revocation — the same effect, through a different switch.

Fundamentals Cavesson adopts

Adopted from the governing rules of the owner's Second Brain Wiki, restated in Cavesson's language. Each item below is an adopted design principle — not yet implemented, and none is presented as built.

  1. 1

    Schema wins Adopted · not implemented

    A governing rules file outranks agent actions. If an agent's action conflicts with the rules, the rules win — and the conflict is flagged to the owner, never silently resolved.

  2. 2

    Provenance on every action Adopted · not implemented

    Every receipt labels the proposer (which agent), the decider (the Human), and the rule version applied. Machine output is never presented as the Human's decision.

  3. 3

    Pointers, not copies Adopted · not implemented

    Agents reference the owner's data; they never copy or edit the raw source. No sensitive values appear in receipts or logs.

  4. 4

    Append-only receipt log Adopted · not implemented

    Corrections are new entries, never rewrites or deletions. The log grows; it is never edited to change what happened.

  5. 5

    Lint/audit pass Adopted · not implemented

    A periodic pass flags contradictions, stale rules, orphan rules, provenance gaps, and sensitive leaks. It flags; it does not silently fix.

  6. 6

    Pending stays pending Adopted · not implemented

    Unapproved or unlabeled agents, rules, and vendors default to denied and stay excluded until the owner approves or labels them. Nothing pending is treated as approved.

  7. 7

    Human checks, machine files Adopted · not implemented

    The machine proposes and records; the Human decides. The machine files the record — it never stands in for the Human's check.

Memory and language Design

Designed, not built, not shipped.

  • Memory is segmented in the general workspace. Each agent's memory is separate. Working in the same workspace does not mean sharing memory.
  • Agents share one file, under the Human's control. It is the single shared surface. No agent changes it on its own.
  • A separate AI watches how agents speak to each other. Its job is to make sure they are not speaking in a hyper language above the Human's understanding. Anything above the Human's understanding gets flagged to the Human.

Machines propose, but humans are the source of all decisions.
