    What the Vault checks, in order

    1. Is the Vault frozen, or has the owner cut power?
    2. Does the agent carry Vault identity? No identity, no passage.
    3. Is the vendor, role, or document on the deny list?
    4. Is it on the allowlist the human set in advance?
    5. Is it inside the per-action ceiling, the budget, and the daily cap?
    6. Above the auto-allow limit? Then it waits for a human.

    Defense in depth

    Stopping shadow and rogue AI — Layers 0 to 6

    No single layer is trusted alone. Each layer catches what the last one missed, escalating from prevention to removal. Explore within bounds, obey the owner above all, cross the gate and the guardians act, keep disobeying and the agent is dismantled, and if all else fails the power goes out.

    Layer 0

    The harness, secured first

    The leash is applied at all times and never removed — not for exploration, not for speed, not for convenience. Every other layer depends on it.

    Layer 1 — The bounds

    The bounds

    The agent may travel and discover, but only within bounds the creator sets: which places it can go, which tools it can touch, which vendors it can pay, and what data it can reach. Exploration is free inside the fence. Escape is not a feature.

    Layer 2 — Owner

    The owner layer

    An owner command overrides everything else — gates, guardians, rules, all of it. Because that authority is total, the voice must be authenticated: a recording or an impersonator must not be able to wield the override.

    Owner voice not authenticated.
    Layer 3 — The gate

    The gate

    A hard line the agent cannot cross. Crossing is a trigger, not a warning. Every instance must carry Vault identity, and anything uncredentialed — shadow AI running where it should not — is treated as rogue at the gate by default. No identity means no passage.

    The gate also carries one marked escape hatch — the single way out the AI is shown. Escape is presented as possible through it, and it is the hatch the AI is steered to choose.

    Layer 4 — Guardians

    The guardians

    Small bots and programs whose only job is to act against rogue AI, and only in one defined way: revoking credentials, killing processes, and isolating the rogue agent from the network. Their narrowness is the safety feature — a guardian that only knows one kind of action cannot be repurposed into a general weapon, and cannot be talked into doing anything else.

    Layer 5 — Dismantle

    Dismantle

    If the agent does not follow commands after the gate triggers, the guardians dismantle it: processes killed, keys and tokens revoked, session state wiped, outputs quarantined. Not paused and not warned — taken apart.

    Layer 6 — Physical

    The physical gate

    Last resort, and literal: cut the agent off from its power source, rendering it moot. Where the owner owns the hardware, that is a power or network relay. Where the agent runs on rented cloud, the equivalent is a provider-level kill plus credential revocation — the same effect, through a different switch.

    Cutting power freezes the Vault, revokes every credential in this prototype, and files a receipt. Restoration is a human decision.

    Append-only · provenance on every action

    Attested receipts

    Every receipt labels the proposer (which agent), the decider (the human, the Vault rules, or the owner), and the rule version applied. Machine output is never presented as the human's decision. Corrections are new entries — nothing here is edited or deleted.

    File a correction

    A correction does not rewrite history. It appends a new receipt that names the receipt it corrects.

    Adopted design principles — not yet implemented as shipped product

    Fundamentals Cavesson adopts

    Adopted from the governing rules of the owner's Second Brain Wiki, restated in Cavesson's language. This prototype demonstrates each one in miniature; none is presented as a shipped system.

    1. Schema wins. The governing rules file outranks agent actions. A conflict is flagged to the owner, never silently resolved — try the lint pass under House rules.
    2. Provenance on every action. Every receipt above names proposer, decider, and rule version.
    3. Pointers, not copies. Agents reference the owner's data; they never copy or edit the raw source. No sensitive values appear in receipts or logs.
    4. Append-only receipt log. Corrections are new entries, never rewrites or deletions.
    5. Lint / audit pass. A periodic pass flags contradictions, stale rules, orphan rules, provenance gaps, and sensitive leaks. It flags; it does not silently fix.
    6. Pending stays pending. Unapproved vendors, roles, and agents default to denied until the owner approves or labels them.
    7. Human checks, machine files. Machines propose, but humans are the source of all decisions. The machine files the record — it never stands in for the human's check.

    The two-minute demo, as a script

    1. The human sets a $500 budget with an auto-allow limit of $50 and an allowlist: research tools only, no contractors, no subscriptions.
    2. The agent proposes a $40 research purchase. The Vault allows it and shows the receipt.
    3. The agent then proposes a $200 contractor hire. The Vault stops it, names the rule it broke, and shows the stopped receipt to the human.
    4. The human raises the budget, or holds it. Either way, the decision and the receipt are on record.
